# Luna 技术架构与核心设计

> **版本**: v2.0
> **更新日期**: 2026/05/11
> **项目定位**: 基于 Java Agent 的动态字节码注入诊断系统核心架构文档

---

## 1. 架构理念

### 1.1 洋葱架构思想 (Flexible Onion Architecture)

Luna 在设计上吸收了洋葱架构的核心思想，即**依赖倒置**与**核心隔离**：

| 原则          | 说明                                         |
|-------------|--------------------------------------------|
| **内层逻辑独立性** | 核心业务逻辑（如注入控制、类型判定、规则匹配）位于中心，不依赖任何外部框架或技术细节    |
| **依赖向内流动**  | 所有的依赖关系都指向内层。Web 接口层引用核心接口，而非核心逻辑引用 Web 接口 |
| **技术实现外置**  | 具体的 ASM 字节码实现、反编译工具、Web 服务器等均作为"可替换"的基础设施实现   |

### 1.2 模块依赖关系


### 4.3 两条注入路径对比

| 特性 | API 实时注入 | 规则自动注入 |
|:---|:---|:---|
| **触发方式** | 用户通过 Web API 手动触发 | 类首次加载时自动触发 |
| **入口类** | `InjectionController` → `InjectionExecutor` | `RuleClassFileTransformer` |
| **Transformer** | `ClassFileTransformerAdapter`（临时注册，用完移除） | `RuleClassFileTransformer`（全局注册，持久存在） |
| **适用场景** | 对已加载的类进行 retransform | 对后续新加载的类自动注入 |
| **注入点来源** | `InjectionCommand` 直接构建 | `RuleManager` 查询匹配规则 → `RuleConverter` 转换 |

## 5. 注入体系详细设计

### 5.1 注入器体系

```mermaid
classDiagram
    class BytecodeInjector {
        <<interface>>
        +inject(InjectionContext, byte[], BytecodeAssembler) byte[]
    }
    class AbstractMethodInjector {
        <<abstract>>
        #inject(InjectionContext, byte[], BytecodeAssembler) byte[]
        #createMethodVisitor(AsmInjectionContext, BytecodeAssembler) MethodVisitor*
        -shouldInjectIntoMethod(String, String, AsmInjectionContext) boolean
    }
    class EnterMethodInjector {
        #createMethodVisitor() MethodVisitor
    }
    class ExitMethodInjector {
        #createMethodVisitor() MethodVisitor
    }
    class AroundMethodInjector {
        #createMethodVisitor() MethodVisitor
    }
    class BeforeLineInjector {
        +inject(InjectionContext, byte[], BytecodeAssembler) byte[]
    }
    class AfterLineInjector {
        +inject(InjectionContext, byte[], BytecodeAssembler) byte[]
    }

    BytecodeInjector <|.. AbstractMethodInjector
    BytecodeInjector <|.. BeforeLineInjector
    BytecodeInjector <|.. AfterLineInjector
    AbstractMethodInjector <|-- EnterMethodInjector
    AbstractMethodInjector <|-- ExitMethodInjector
    AbstractMethodInjector <|-- AroundMethodInjector
```

**设计模式**：`AbstractMethodInjector` 采用**模板方法模式**，定义了 `inject()` 的骨架流程（ClassReader → ClassVisitor → ClassWriter），子类只需实现 `createMethodVisitor()` 返回对应的 MethodVisitor 即可。

**两种实现路径**：

| 实现路径 | 使用 API | 适用注入器 | 特点 |
|:---|:---|:---|:---|
| **Visitor API** | `ClassReader.accept(ClassVisitor, ...)` | `EnterMethodInjector`, `ExitMethodInjector`, `AroundMethodInjector` | 流式处理，内存效率高，适合方法级注入 |
| **Tree API** | `ClassNode` + `MethodNode.instructions.insertBefore/insert` | `BeforeLineInjector`, `AfterLineInjector` | 可随机访问指令列表，适合行号级精确插入 |

### 5.2 Visitor 体系

```mermaid
classDiagram
    class MethodVisitor {
        <<ASM>>
    }
    class EnterMethodVisitor {
        -BytecodeAssembler assembler
        -AsmInjectionContext context
        +visitCode() 注入代码
    }
    class ExitMethodVisitor {
        -BytecodeAssembler assembler
        -AsmInjectionContext context
        +visitInsn(opcode) IRETURN~RETURN 时注入
    }
    class AroundMethodVisitor {
        +AroundMethodVisitor() 组合 Enter + Exit
    }
    class LineNumberVisitor {
        -BytecodeAssembler assembler
        -AsmInjectionContext context
        -boolean beforeLine
        -int targetLineNumber
        -boolean lineNumberVisited
        -boolean injected
        +visitLineNumber(line, start) 行号匹配时注入
        +visitInsn(opcode) return 前注入（afterLine 模式）
        +visitEnd() 兜底注入
    }

    MethodVisitor <|-- EnterMethodVisitor
    MethodVisitor <|-- ExitMethodVisitor
    MethodVisitor <|-- AroundMethodVisitor
    MethodVisitor <|-- LineNumberVisitor
    AroundMethodVisitor *-- EnterMethodVisitor
    AroundMethodVisitor *-- ExitMethodVisitor
```

**各 Visitor 注入时机**：

| Visitor | 注入时机 | 对应 Java 伪代码 |
|:---|:---|:---|
| `EnterMethodVisitor` | `visitCode()` 回调 | `void method() { /* ← 注入点 */ ... }` |
| `ExitMethodVisitor` | `visitInsn()` 拦截 `IRETURN`~`RETURN` | `void method() { ... /* ← return 前 */ return; }` |
| `AroundMethodVisitor` | 组合 `EnterMethodVisitor` + `ExitMethodVisitor` | 进入 + 退出双重注入 |
| `LineNumberVisitor` | `visitLineNumber()` 匹配目标行号 | 在指定源码行处注入 |

### 5.3 TreeApiBytecodeHelper

`TreeApiBytecodeHelper` 是 Visitor API → Tree API 的**桥接工具**，解决行号注入器需要 `InsnList` 的问题：

```mermaid
flowchart LR
    A[BytecodeAssembler] -->|assemble| B[InsnListCollector]
    B -->|收集指令| C[List of AbstractInsnNode]
    C -->|toInsnList| D[InsnList]
    D -->|insertBefore/insert| E[MethodNode.instructions]
```

**核心机制**：
- `InsnListCollector` 是一个内部类，继承 `MethodVisitor`
- 将 `BytecodeAssembler` 输出的 Visitor API 调用拦截并转换为 `AbstractInsnNode` 列表
- 最终通过 `toInsnList()` 转为 `InsnList`，供 `BeforeLineInjector`/`AfterLineInjector` 使用 `insertBefore()`/`insert()` 插入

### 5.4 ExpressionBytecodeAssembler

`ExpressionBytecodeAssembler` 是核心的字节码组装器，继承 `BaseAsmBytecodeAssembler`，负责将注入代码协议翻译为 ASM 字节码指令：

**协议分发**：

```mermaid
flowchart TD
    A[getCode 内容] --> B{解析协议前缀}
    B -->|log:xxx| C[generateLogBytecode]
    B -->|snapshot:true| D[generateSnapshotBytecode]
    B -->|trace:start| E[generateTraceBytecode - start]
    B -->|trace:end:N| F[generateTraceBytecode - end]
    B -->|trace:alert:N| G[generateTraceBytecode - alert]
```

**条件前缀解析**：

```
${condition}::protocol:content
     ↑           ↑        ↑
  条件表达式    协议类型   协议内容
```

- 若存在 `${condition}::` 前缀，先注册条件到 `ConditionRegistry`，并在字节码中生成条件检查跳转
- 若不存在条件前缀，调用 `ConditionRegistry.unregister()` 移除旧条件

**三种协议的字节码生成**：

| 协议 | 生成逻辑 | 等价 Java 伪代码 |
|:---|:---|:---|
| `log:消息 $1 $varName` | 解析 `$N` 参数引用和 `$varName` 局部变量引用 → `String.format()` + `LunaSpy.onLog()` | `LunaSpy.onLog(String.format("消息 %s %s", $1, varName))` |
| `snapshot:true` | 收集参数 + 局部变量 → `Object[]` + `String[]` → `LunaSpy.onSnapshot()` | `LunaSpy.onSnapshot(pointId, new Object[]{...}, new String[]{...})` |
| `trace:start` | 直接调用 `LunaSpy.onTraceStart()` | `LunaSpy.onTraceStart()` |
| `trace:end:N` | 调用 `LunaSpy.onTraceEnd(className, methodName, threshold)` | `LunaSpy.onTraceEnd("ClassName", "methodName", N)` |
| `trace:alert:N` | 调用 `LunaSpy.onTraceAlert(className, methodName, threshold)` | `LunaSpy.onTraceAlert("ClassName", "methodName", N)` |

**参数引用解析**（`parseExpression` 方法）：
- `$1`, `$2`, ... → 方法参数引用，通过 `ParameterInfo` 映射到局部变量 Slot
- `$varName` → 局部变量引用，通过 `LocalVarInfo` 匹配变量名
- 混合文本和引用时，使用 `String.format()` 格式化

**条件检查字节码**（`generateConditionCheck` 方法）：

```java
// 等价 Java 伪代码：
EvaluationContext ctx = EvaluationContext.getThreadLocal();
ctx.bind("param[1]", $1);
ctx.bind("param[2]", $2);
ctx.bind("varName", $varName);
if (!ConditionRegistry.test(injectionId, ctx)) {
    goto endLabel;
}
// ... 实际注入代码 ...
endLabel:
```

### 5.5 LocalVariableScanner

基于 ASM Tree API 扫描指定行号处**可见**的局部变量：

**核心流程**：
1. 解析字节码为 `ClassNode`
2. 定位目标方法
3. 构建 `LabelNode → 行号` 映射（`buildLabelLineMap`）
4. 遍历 `LocalVariableNode` 列表，判断变量在目标行号处是否可见
5. 可见性判断：`startLine ≤ targetLine ≤ endLine`

**`excludeSameLineStart` 参数**：
- `true`（BeforeLine 注入使用）：排除 `startLine == targetLine` 的变量，避免访问尚未初始化的变量
- `false`（AfterLine 注入使用）：包含 `startLine == targetLine` 的变量

**降级策略**：当 Label 无法直接映射到行号时，通过 `findNearestPrecedingLine()` 查找最近的先前行号作为近似值。

### 5.6 ClassLoaderAwareClassWriter

重写 `getCommonSuperClass()` 方法，使用指定的 ClassLoader 进行类查找：

```java
// 核心逻辑：
protected String getCommonSuperClass(String type1, String type2) {
    Class<?> class1 = Class.forName(type1, false, targetClassLoader);
    Class<?> class2 = Class.forName(type2, false, targetClassLoader);
    // ... 类型继承关系判断 ...
}
```

- 使用 `COMPUTE_MAXS | COMPUTE_FRAMES` 标志，自动计算栈帧和最大操作数栈
- 解决了默认 `ClassWriter` 在 Agent 场景下因 ClassLoader 不一致导致 `ClassNotFoundException` 的问题

## 6. 条件表达式引擎

### 6.1 完整流程

```mermaid
flowchart LR
```

### 6.2 词法分析：Tokenizer

将表达式字符串转换为 Token 序列，支持的 Token 类型：

| Token 类型 | 示例 | 说明 |
|:---|:---|:---|
| `DOLLAR_BRACE_OPEN` | `${` | Luna 条件语法糖开始 |
| `BRACE_CLOSE` | `}` | 条件语法糖结束 |
| `IDENTIFIER` | `age`, `param` | 变量名 |
| `NUMBER` | `18`, `3.14` | 整数或浮点数 |
| `STRING` | `"active"`, `'hello'` | 字符串字面量 |
| `BOOLEAN` | `true`, `false` | 布尔字面量 |
| `EQUAL` | `==` | 等于 |
| `NOT_EQUAL` | `!=` | 不等于 |
| `GREATER` / `GREATER_EQUAL` | `>`, `>=` | 大于 / 大于等于 |
| `LESS` / `LESS_EQUAL` | `<`, `<=` | 小于 / 小于等于 |
| `AND` | `&&` | 逻辑与 |
| `OR` | `\|\|` | 逻辑或 |
| `NOT` | `!` | 逻辑非 |
| `PLUS` / `MINUS` / `MULTIPLY` / `DIVIDE` | `+`, `-`, `*`, `/` | 算术运算 |
| `DOT` | `.` | 属性访问 |
| `LEFT_BRACKET` / `RIGHT_BRACKET` | `[`, `]` | 数组下标 |
| `LEFT_PAREN` / `RIGHT_PAREN` | `(`, `)` | 括号 |
| `COMMA` | `,` | 逗号 |

### 6.3 语法分析：ExpressionParser

递归下降解析器，运算符优先级从低到高：

```
parse() → parseLogicalOr()
  → parseLogicalAnd()        (||)
    → parseEquality()        (&&)
      → parseComparison()    (==, !=)
        → parseAdditive()    (>, >=, <, <=)
          → parseMultiplicative() (+, -)
            → parseUnary()   (*, /)
              → parsePrimary() (!, -)
```

**`parsePrimary()` 处理**：
- 数字 → `ConstantNode`
- 字符串 → `ConstantNode`
- 布尔值 → `ConstantNode`
- 标识符 + `(` → `FunctionCallNode`
- 标识符 + `[` → `VariableNode`（如 `param[0]`）
- 标识符 → `VariableNode`
- `(` → 递归解析子表达式
- 后缀 `.property` → `PropertyAccessNode`

### 6.4 AST 节点体系

```mermaid

        -ExpressionNode left
```

### 6.5 预编译缓存：ConditionRegistry

- 内部使用 `ConcurrentHashMap<String, ExpressionNode>` 缓存已解析的 AST
- `register(injectionId, expression)`：解析表达式并缓存 AST
- `unregister(injectionId)`：移除缓存
- `test(injectionId, context)`：直接对缓存的 AST 求值，避免重复解析
- 无条件时默认返回 `true`（放行）
- 求值异常时返回 `false`（静默跳过，不影响业务）

### 6.6 运行时求值：EvaluationContext

- 使用 `ThreadLocal<EvaluationContext>` 实现线程复用，减少 GC
- `getThreadLocal()` 自动清空上下文
- 支持绑定变量：`bind(name, value)`
- 支持参数绑定：`bindParams(Object...)` → `param[0]`, `arg0`
- 支持 `this` 引用和返回值绑定
- `asMap()` 返回底层 Map 供 `ExpressionNode.evaluate()` 使用

### 6.7 字节码编译：ExpressionBytecodeGenerator

将表达式编译为独立的 `.class` 字节码：
- 生成 `ExpressionEvaluator` 类，包含 `static Object evaluate(Object context)` 方法
- 运算逻辑委托给 `ExpressionUtils` 的静态方法（如 `add()`, `equals()`, `greaterThan()` 等）
- 变量访问通过 `ExpressionUtils.getVariableValue(context, name)` 从上下文获取

## 8. 通信与数据流

### 8.1 LunaSpy

`LunaSpy` 是注入字节码与 Agent 核心通信的桥梁，被注入的方法会直接调用其静态方法：

| 方法 | 签名 | 说明 |
|:---|:---|:---|
| `onLog` | `(String) → void` | 投递日志消息到 RingBuffer |
| `onSnapshot` | `(String, Object[], String[]) → void` | 捕获变量快照并序列化后投递 |
| `onTraceStart` | `() → void` | 记录方法入口时间（ThreadLocal） |
| `onTraceEnd` | `(String, String, long) → void` | 计算耗时并投递追踪消息 |
| `onTraceAlert` | `(String, String, long) → void` | 超阈值时投递告警消息 |

**关键设计**：
- `LOG_BUFFER`: `RingBuffer<String>(4096)` — 所有数据统一投递到同一个 RingBuffer
- `TRACE_START_TIME`: `ThreadLocal<Long>` — 每线程独立的计时器
- 所有方法极度轻量，`onSnapshot` 和 `onTraceEnd/Alert` 使用 `try-catch(Throwable)` 防御

### 8.2 RingBuffer

```mermaid
flowchart LR
    subgraph "生产者（业务线程）"
        P1[onLog] --> RB[RingBuffer]
        P2[onSnapshot] --> RB
        P3[onTraceEnd] --> RB
    end
    subgraph "消费者（LogDispatcher 线程）"
        RB --> C[LogDispatcher]
        C --> WS[WebSocket Sessions]
    end
```

**MPSC 无锁队列实现**：

| 特性 | 实现方式 |
|:---|:---|
| **数据结构** | `AtomicReferenceArray<T>` + 容量自动取整为 2 的幂次方 |
| **写索引** | `AtomicLong writeIndex`，CAS 争抢写槽位 |
| **读索引** | `AtomicLong readIndex`，单消费者安全推进 |
| **满队列处理** | `offer()` 返回 `false`，**丢弃不阻塞**（保护业务线程） |
| **内存可见性** | `buffer.lazySet()` 减少内存屏障开销 |
| **容量** | 默认 4096 |

### 8.3 WebSocket 三层架构

```mermaid
flowchart TD
    subgraph "Servlet 层"
        LWS[LogWebSocketServlet] --> LWE[LogWebSocketEndpoint]
    end
    subgraph "Endpoint 层"
        LWE -->|onConnect| LD[LogDispatcher]
        LWE -->|onClose| LD
    end
    subgraph "Dispatcher 层"
        LD -->|后台线程轮询| RB[LunaSpy.LOG_BUFFER]
        RB -->|poll| LD
        LD -->|broadcast| SS[WebSocket Sessions]
    end
```

| 层次 | 类 | 职责 |
|:---|:---|:---|
| **Servlet 层** | `LogWebSocketServlet` | Jetty WebSocket Servlet 适配器，配置超时和消息大小限制 |
| **Endpoint 层** | `LogWebSocketEndpoint` | 管理 WebSocket 连接生命周期，维护 Session 注册/注销 |
| **Dispatcher 层** | `LogDispatcher` | 后台守护线程轮询 `RingBuffer.poll()`，`sendStringByFuture()` 异步广播 |

**消费循环**：
- `LogDispatcher` 后台线程持续调用 `LunaSpy.LOG_BUFFER.poll()`
- 有数据时广播给所有 WebSocket Session
- 无数据时 `Thread.sleep(1)` 避免 CPU 空转
- 无连接时仍消费数据（丢弃），防止 RingBuffer 积压导致 OOM

### 12.2 DefaultClassTransformer

核心转换逻辑：
1. 从 `BytecodeInjectorRegistry` 查找注入器
2. 从 `BytecodeAssemblerRegistry` 查找组装器
3. 调用 `injector.inject(context, bytecode, assembler)` 执行注入
4. 返回 `TransformerResult`

### 12.3 ClassFileTransformerAdapter

- **临时注册**：在 `InjectionExecutor.execute()` 中注册，retransform 完成后移除
- **多点聚合**：对同一类的多个注入点，按顺序逐个执行 `classTransformer.transform()`
- **结果收集**：`CopyOnWriteArrayList<InjectionResult>` 收集每个注入点的执行结果

### 12.4 RuleClassFileTransformer

全局规则自动转换器：
- **仅首次加载**：`classBeingRedefined == null` 时才处理（新加载的类）
- **规则匹配**：调用 `RuleManager.findRulesForClass()` 查找匹配规则
- **规则转换**：通过 `RuleConverter.convert()` 将规则转为注入点
- **逐个执行**：对每个注入点调用 `DefaultClassTransformer.transform()`

## 13. 类隔离策略

为了确保 Luna 的依赖（如 Jetty, ASM, CFR, FastJSON）不影响目标进程：

### 策略一：隔离加载

- 自定义 `LunaAgentClassLoader`（继承 `URLClassLoader`）
- Agent 入口类 `Agent` 使用 `SystemClassLoader` 加载
- 在 `executeWithAgentClassLoader()` 中切换到 `LunaAgentClassLoader`，通过反射调用 `startAgent()`
- **打破双亲委派**：除了 `java.*` 等核心类外，Luna 自身的类均由该 ClassLoader 隔离加载

### 策略二：字节码更名 (Shading)

- 利用 Maven Shade Plugin，将 `org.objectweb.asm` 重命名为 `fun.efto.luna.shade.asm`
- 即使宿主应用也依赖了不同版本的 ASM，由于全限定名不同，加载时完全隔离

### 策略三：Bootstrap ClassLoader 注入

- 通过 `inst.appendToBootstrapClassLoaderSearch(new JarFile(agentJarPath))` 将 Agent JAR 加入 Bootstrap ClassLoader 搜索路径
- 使得 `LunaSpy` 类在所有 ClassLoader 中均可见，业务代码可直接调用

## 14. JVM Attach 机制

Luna 使用 JDK 自带的 `com.sun.tools.attach.VirtualMachine` API 实现运行时注入：

```java
// Attacher 核心逻辑
VirtualMachineDescriptor selected = waitUserInput();  // 列出 JVM 进程，用户选择
VirtualMachine vm = VirtualMachine.attach(selected);
vm.loadAgent(agentJarPath);  // 加载 Agent
// ... 使用完毕后 ...
vm.detach();
```

**Agent 入口方法**：
- `premain()`：通过 `-javaagent` 参数启动时调用
- `agentmain()`：通过 Attach API 动态加载时调用
- 两者均委托给 `executeWithAgentClassLoader()` → `startAgent()`

## 15. Luna 自生日志处理

为了确保 Agent 自身的运行日志与目标应用的日志及配置完全隔离：

1. **独立初始化**：在 `LoggerInitializer` 中，通过 `Configurator.initialize("luna-agent", ...)` 显式创建一个名为 `luna-agent` 的日志上下文
2. **配置隔离**：显式指定加载 `luna-log4j2.xml` 配置文件
3. **防冲突设计**：
    - Luna 使用的 Log4j2 相关类库在打包阶段通过 `shade` 进行重定位
    - 日志初始化动作被放置在 Agent 启动的最早期阶段（`startAgent()` 第一步）

## 16. 多次注入与类缓存管理

Luna 会在内存中维护一个双层缓存（`BytecodeCache`）：

- **bytecodeCache**：`ConcurrentHashMap<String, byte[]>` — 缓存字节码
- **analysisCache**：`ConcurrentHashMap<String, Object>` — 缓存分析结果

**同一个类的多次注入处理**：遵循 **"Clean Slate + Re-apply"** 策略

1. `InjectionPointRegistry` 维护每个类的所有活跃注入点
2. `InjectionExecutor.execute()` 注册新注入点后，获取该类所有注入点
3. 创建 `ClassFileTransformerAdapter`，在 `transform()` 中按顺序逐个应用所有注入点
4. 调用 `retransformClasses` 覆盖载入

**移除注入点**：
- `InjectionPointRegistry.removeById()` 移除指定注入点
- 若该类仍有剩余注入点，重新 retransform（只应用剩余注入点）
- 若该类无剩余注入点，retransform 回原始字节码（无注入点匹配时 `transform()` 返回 `null`）

## 17. 扩展性机制与演进路径

### 17.1 当前扩展方式

| 扩展方式 | 机制 | 示例 |
|:---|:---|:---|
| **注入器扩展** | 通过 `BytecodeInjectorRegistry` 注册新的 `BytecodeInjector` | 添加新的方法级注入策略 |
| **组装器扩展** | 通过 `BytecodeAssemblerRegistry` 注册新的 `BytecodeAssembler` | 添加新的代码类型（如 `CodeType.JAVA`） |
| **分析器扩展** | 通过 `AnalyzerRegistry` 注册新的 `ClassAnalyzer` | 添加基于其他引擎的分析器 |
| **模板扩展** | 通过 `TemplateRegistry` 注册新的 `RuleTemplate` | 添加社区模板 |
| **初始化器扩展** | 通过 `ServiceLoader` 发现 `Initializer` 实现 | 添加插件化初始化逻辑 |

### 17.2 未来插件化演进路径

当出现以下情况时，再考虑拆分独立的 `luna-plugin-api` 模块：

- 有 **3+ 个复杂插件**（每个 >10 个类）
- 需要支持**第三方开发者**
- 插件有**复杂的外部依赖**（如 Spring、MyBatis）

当前阶段，显式注册 + ServiceLoader 的方式已满足需求，避免过度设计。
