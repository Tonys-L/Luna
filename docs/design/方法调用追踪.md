# Luna Invocation Trace Capability Design

> 日期：2026-05-29
> 目标：设计 Luna 的 Invocation Trace Capability，用于构建 Runtime Invocation Graph，为 Diagnostics、Visualization、AI Runtime Reasoning 提供基础。
> 核心原则：Invocation Trace 是 Runtime Diagnostics Infrastructure，而不是普通日志插件。

---

# 1. Capability 定位

Invocation Trace Capability 的目标不是：

```text
打印 method trace 日志
```

而是：

# 构建 Runtime Execution Graph

例如：

```text
HTTP Request
  -> OrderController.create()
      -> OrderService.create()
          -> InventoryService.lock()
              -> RedisClient.lock()
          -> PaymentService.pay()
              -> JdbcTemplate.execute()
```

本质上：

```text
这是 Runtime Invocation Relationship
```

而不是：

```text
几条日志
```

---

# 2. 核心定位

Invocation Trace Capability 属于：

```text
Runtime Support Capability
```

因为：

后续：

* Runtime Explainability
* AI Diagnostics
* Runtime Visualization
* Causality Analysis
* Bottleneck Detection

都会依赖它。

---

# 3. 核心设计原则

---

# 3.1 Structured First

所有输出必须：

```text
结构化
```

而不是：

```text
纯文本 trace
```

因为：

* AI
* CLI
* Web UI
* Visualization
* Explainability

都依赖结构化 graph。

---

# 3.2 Runtime Graph First

官方负责：

* invocation graph
* runtime relationship
* observation event
* context propagation

不负责：

* APM 平台
* Metrics 平台
* 分布式 tracing 产品

---

# 3.3 Runtime Safety First

必须优先保证：

* bounded memory
* snapshot isolation
* rollback
* sampling
* cleanup
* runtime governance

否则：

Invocation Trace 很容易拖垮 JVM。

---

# 4. Runtime Invocation Model

---

# 4.1 ActiveInvocation

运行中的 invocation：

```java
public class ActiveInvocation {

    private String invocationId;

    private String traceId;

    private String parentInvocationId;

    private long startNanoTime;

    private long threadId;

    private String className;

    private String methodName;

    private String descriptor;

    private InvocationSnapshot arguments;
}
```

---

# 4.2 CompletedInvocation

结束后的 immutable invocation：

```java
public class CompletedInvocation {

    private String invocationId;

    private String traceId;

    private String parentInvocationId;

    private long startTime;

    private long endTime;

    private long duration;

    private long threadId;

    private String threadName;

    private String className;

    private String methodName;

    private String descriptor;

    private InvocationSnapshot arguments;

    private InvocationSnapshot returnValue;

    private ThrowableSnapshot throwable;

    private InvocationStatus status;

    private Map<String, String> tags;
}
```

---

# 4.3 为什么区分 Active / Completed

如果直接共享一个 InvocationNode：

```text
边执行边修改对象
```

会导致：

* 并发语义混乱
* snapshot 不稳定
* projection 不一致
* replay 困难

因此：

```text
运行态对象
```

与：

```text
历史 observation
```

必须分离。

# 6. Invocation Context Propagation

这是整个 capability 的核心。

---

# 6.1 为什么重要

没有：

```text
current invocation context
```

则：

```text
A()
  -> B()
      -> C()
```

无法形成 graph。

只能变成：

```text
三条独立日志
```

---

# 6.2 Capability

建议新增：

```text
InjectionScopedRuntimeStateCapability
```

负责：

* current invocation
* trace context
* correlation context
* request-scoped state

---

# 6.3 InvocationContextCarrier

不要直接绑定：

```text
ThreadLocal
```

正确抽象：

```java
public interface InvocationContextCarrier {

    ActiveInvocation current();

    void push(ActiveInvocation invocation);

    void pop();

    void propagate(InvocationContext context);
}
```

---

# 6.4 Phase 1 Backend

Phase 1：

```text
ThreadLocal-backed
```

即可。

但：

```text
ThreadLocal != Capability
```

必须明确。

---

# 7. Runtime Observation Model

---

# 7.1 Observation 是 Append-only Event

Observation Store 不应：

```text
直接存 graph
```

而应：

```text
存 append-only runtime events
```

graph 属于：

```text
projection
```

---

# 7.2 InvocationStartedEvent

```java
public class InvocationStartedEvent
        implements RuntimeObservation {

    private ActiveInvocation invocation;
}
```

---

# 7.3 InvocationCompletedEvent

```java
public class InvocationCompletedEvent
        implements RuntimeObservation {

    private CompletedInvocation invocation;
}
```

---

# 7.4 InvocationFailedEvent

```java
public class InvocationFailedEvent
        implements RuntimeObservation {

    private CompletedInvocation invocation;
}
```

---

# 8. Observation Store

---

# 8.1 ObservationStore

```java
public interface ObservationStore {

    void append(RuntimeObservation observation);

    Stream<RuntimeObservation> stream(
            ObservationQuery query);
}
```

---

# 8.2 为什么需要 Stream

未来需要：

* replay
* AI diagnostics
* timeline analysis
* causality analysis
* graph projection

因此：

```text
query list
```

不够。

# 9. Projection Model

Visualization 不应直接读 event stream。

应该：

```text
event stream
    -> projection
        -> visualization
```

---

# 9.1 InvocationGraphProjection

```java
public interface InvocationGraphProjection {

    InvocationGraph project(
            Stream<RuntimeObservation> observations);
}
```

---

# 10. Snapshot Model

---

# 10.1 禁止持有原始对象

不要：

```java
Object structuredValue;
```

否则：

* classloader leak
* memory retention
* lazy loading
* deep object graph

都会出问题。

---

# 10.2 Snapshot 必须 Immutable

```java
public class InvocationSnapshot {

    private SnapshotType type;

    private String displayValue;

    private Map<String, String> fields;

    private boolean truncated;
}
```

---

# 10.3 Snapshot Policy

```java
public class SnapshotPolicy {

    private int maxDepth;

    private int maxCollectionSize;

    private int maxStringLength;

    private int maxFieldCount;

    private boolean includePrivateFields;
}
```

---

# 11. Sampling Strategy

这是生产环境最关键的能力之一。

---

# 11.1 Root Sampling

采样必须：

```text
以 trace root 为边界
```

而不是：

```text
method-level random sampling
```

否则：

```text
graph 会断裂
```

---

# 11.2 SamplingPolicy

```java
public interface SamplingPolicy {

    boolean shouldStartTrace(
            InvocationStartContext context);
}
```

必须治理。

---

# 12.1 必须支持

* max active traces
* max invocation depth
* rate limit
* timeout cleanup
* snapshot size limit
* backpressure

---

# 12.2 Governance Capability

建议：


# 16.2 AI Diagnostic Flow

```bash

```

1. 创建 trace injection
2. 创建 jdbc timing injection
3. 创建 thread contention injection
4. 收集 runtime observations
5. 构建 invocation graph
6. 分析 causality
7. 输出 explain report
8. 自动 cleanup session
