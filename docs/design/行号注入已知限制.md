# Luna 行号注入 — 已知限制与未完全支持场景

> 本文档记录当前行号注入功能中尚未完全支持或存在已知限制的场景，供开发者和用户参考。
> 更新日期：2026/05/30

---

## 1. 编译调试信息依赖

### 1.1 无 `-g:none` 编译的类

| 项目 | 说明 |
|------|------|
| **影响** | 行号注入完全不可用 |
| **原因** | 字节码中无 `LineNumberTable`，无法将源码行号映射到字节码指令 |
| **当前行为** | 注入时抛出异常：`类缺少调试信息(LineNumberTable)，请使用 -g 或 -g:lines 编译` |
| **规避** | 使用默认编译选项（`javac` 默认包含 `-g`），或显式添加 `-g:lines` |
| **改进方向** | 无 `LineNumberTable` 时，可退化为方法级注入（`METHOD_ENTER`/`METHOD_EXIT`），但无法精确定位到行 |

### 1.2 仅有 `-g:lines`（无变量表）的类

| 项目 | 说明 |
|------|------|
| **影响** | 行号注入可用，但局部变量捕获为空 |
| **原因** | 字节码中无 `LocalVariableTable`，无法获取变量名和作用域信息 |
| **当前行为** | `LocalVariableScanner` 返回空列表，`snapshot` 只能捕获方法参数（通过描述符推断），无法捕获局部变量 |
| **规避** | 使用 `-g` 或 `-g:vars` 编译 |
| **改进方向** | 可通过字节码分析（数据流分析）推断变量槽位，但无法获取变量名，只能以 `slot_1`、`slot_2` 等索引标识 |

## 2. Lambda 与匿名类

### 2.1 Lambda 表达式注入

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 部分支持 |
| **可用方式** | 通过 `lambda$方法名$N` 合成方法名注入（`GET /api/line-numbers` 会返回这些方法） |
| **限制 1** | 用户无法从源码视图直接选择 lambda 行号注入——需要理解合成方法名与源码 lambda 的对应关系 |
| **限制 2** | 非静态 lambda 中，外部类引用通过 `this$0` 传入，捕获的 `this` 是 lambda 实例而非外部类实例 |
| **限制 3** | lambda 捕获的外部变量（effectively final）作为合成方法的额外参数传入，变量名可能被编译器修改（如 `val$item`） |
| **改进方向** | UI 层面：在源码视图中标注 lambda 行对应的合成方法名，支持一键选择 |

### 2.2 方法引用（`Class::method`）

| 项目 | 说明 |
|------|------|
| **支持程度** | ❌ 不支持 |
| **原因** | 方法引用 `Class::method` 本身只是一条 `invokedynamic` 指令，没有独立的字节码方法体可供注入 |
| **改进方向** | 如果需要拦截方法引用，应注入到被引用的目标方法中 |

## 3. 行号映射精度

### 3.1 同一行多条指令

| 项目 | 说明 |
|------|------|
| **影响** | 一行 Java 代码编译为多条字节码指令时，`line_before` 只在第一个指令前触发 |
| **示例** | `int x = a.b().c();` 编译为 3 条 `INVOKEVIRTUAL` + 1 条 `ISTORE`，`line_before` 只在第一条 `INVOKEVIRTUAL` 前触发 |
| **当前行为** | `BeforeLineInjector` 匹配到第一个 `LineNumberNode` 后 `break`，只注入一次 |
| **影响评估** | 🟡 中等——大多数场景下行为正确（行执行前触发），但无法在链式调用的中间步骤触发 |
| **改进方向** | 可增加 `line_each_instruction` 注入类型，在同一行的每条指令前都触发 |

### 3.2 空/注释行

| 项目 | 说明 |
|------|------|
| **影响** | 空/注释行在字节码中没有对应的 `LineNumberNode` |
| **当前行为** | 注入时抛出 `line X not found` 异常 |
| **改进方向** | 自动调整到该行后第一个有效指令行，或在前端 UI 中灰化不可注入的行号 |

### 3.3 多 return 方法中的 line_after

| 项目 | 说明 |
|------|------|
| **修复状态** | ✅ 已修复（return 行的 `line_after` 现在在 return 指令之前插入） |
| **语义** | `line_after` 在 return 行 = "return 语句执行后、方法返回前"——能访问到 return 值对应的变量 |

## 4. 异常处理

### 4.1 catch 块内变量捕获

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 部分支持 |
| **限制** | catch 块中的异常参数 `e` 的 `LocalVariableNode.start` 可能指向 catch 块入口，`LocalVariableScanner` 的行号映射可能不精确 |
| **当前行为** | 在某些编译器输出中，catch 块内的异常对象 `e` 可能被判定为不可见 |
| **规避** | 使用 `snapshot` 时检查返回的变量列表，确认异常对象是否被捕获 |
| **改进方向** | 增强 `LocalVariableScanner` 对异常处理块的作用域判断逻辑 |

### 4.2 try-with-resources 变量

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 未验证 |
| **原因** | try-with-resources 编译后生成大量合成代码（`addSuppressed` 等），变量作用域可能不符合直觉 |
| **改进方向** | 需要专项测试验证 |

## 5. 并发与线程安全

### 5.1 多线程同时执行同一注入行

| 项目 | 说明 |
|------|------|
| **支持程度** | ✅ 支持 |
| **说明** | 每个线程独立执行注入代码，`ProbeOutput.BUFFER` 是无锁 `RingBuffer`，线程安全 |
| **注意** | 高并发场景下 `RingBuffer` 可能丢弃旧消息（容量 4096） |

---

## 6. 类加载器与模块化

### 6.1 不同 ClassLoader 加载的类

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 部分支持 |
| **限制** | `GlobalClassFileTransformer` 通过 `Instrumentation.retransformClasses()` 修改类，对大多数 ClassLoader 加载的类有效。但 Bootstrap ClassLoader 加载的核心类（如 `java.lang.String`）默认不可修改 |
| **改进方向** | 增加安全策略，明确禁止/允许注入系统类 |

### 6.2 JPMS 模块化环境

| 项目 | 说明 |
|------|------|
| **支持程度** | ❌ 未验证 |
| **原因** | 模块化环境中，类的反射和 instrumentation 访问需要 `--add-opens` 等参数 |
| **改进方向** | 需要专项测试 |

## 7. 其他 JVM 语言

### 7.1 Kotlin

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 部分支持 |
| **限制** | Kotlin 编译器生成的变量名可能带有后缀（如 `$this`、`$i$a`），行号映射可能不直观（Kotlin 的行号表可能包含合成代码行） |

### 7.2 Scala / Groovy

| 项目 | 说明 |
|------|------|
| **支持程度** | ❌ 未验证 |
| **原因** | Scala 编译器生成大量合成变量和方法，行号映射可能不直观 |

---

## 8. 性能限制

### 8.1 循环内高频触发

| 项目 | 说明 |
|------|------|
| **支持程度** | ✅ 支持（有上限） |
| **说明** | 注入代码本身是轻量的（`RingBuffer.offer()`），但 `RingBuffer` 容量为 4096，超过后旧消息被丢弃 |
| **注意** | `snapshot` 捕获比 `log` 更重（涉及 `Object[]` 创建和 JSON 序列化），在百万次/秒循环中可能产生 GC 压力 |

### 8.2 大量类同时注入

| 项目 | 说明 |
|------|------|
| **支持程度** | ⚠️ 未压测 |
| **原因** | 每个类的 `retransform` 需要 JVM 停顿（safepoint），大量类同时 retransform 可能导致应用暂停 |

---
