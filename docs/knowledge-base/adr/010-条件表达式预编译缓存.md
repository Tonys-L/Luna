# ADR-010: 条件表达式预编译缓存

## 状态

Accepted

## 背景

Luna 支持条件表达式（如 `${userId > 0}::log("user info")`），注入代码在每次业务方法调用时对条件表达式求值，决定是否执行探针逻辑。

条件表达式的求值过程包括：词法分析 → 语法分析 → AST 构建 → 求值。如果在每次方法调用时都重新解析表达式字符串生成 AST，性能不可接受——一个被频繁调用的业务方法可能每秒执行数千次，重复解析 AST 的开销远超求值本身。

## 方案选项

### 选项 A: 每次运行时解析表达式

每次方法调用时，从表达式字符串重新解析生成 AST 并求值。

优点：
- 实现简单，无需缓存管理
- 无内存占用（不缓存 AST）
- 表达式动态变更时自动生效

缺点：
- 重复解析 AST 性能不可接受
- 高频调用场景下成为性能瓶颈
- 违反"注入代码不能影响业务性能"的不变量

### 选项 B: ConditionRegistry 预编译缓存 AST

ConditionRegistry 在注入时预编译表达式为 AST 并缓存，运行时直接对缓存的 AST 求值。

优点：
- 避免重复解析，求值 O(1)
- 高频调用场景下性能可控
- 符合"注入代码不能影响业务性能"的不变量

缺点：
- 内存占用（AST 缓存）
- 表达式变更时需更新缓存
- 需要管理缓存生命周期（插件卸载时清理）

## 决策

选择**选项 B：ConditionRegistry 预编译缓存 AST**。

条件表达式在每次业务方法调用时求值，重复解析 AST 的性能开销不可接受。预编译缓存将解析开销从 O(n)/次降低到 O(1)/次（仅求值），是保证注入代码不影响业务性能的必要措施。AST 缓存的内存占用是可控的（注入点数量有限），缓存生命周期随插件生命周期管理。

## 影响

- ConditionRegistry 在注入时预编译表达式为 AST 并缓存
- 运行时直接对缓存的 AST 求值，跳过解析步骤
- 插件卸载时清理关联的 AST 缓存
- 表达式变更时需更新缓存（重新编译）
