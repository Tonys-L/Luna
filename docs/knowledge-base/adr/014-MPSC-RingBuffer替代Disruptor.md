# ADR-014: MPSC RingBuffer 而非 Disruptor

## 状态

Accepted

## 背景

Luna 的注入代码在业务线程中执行，产生的探针数据（ProbeMessage）需要从业务线程传输到消费线程（LogDispatcher）。这个数据传输通道必须满足以下约束：

1. **零阻塞**：业务线程绝对不能被阻塞，否则会影响目标应用的性能和稳定性
2. **低延迟**：数据传输延迟应尽可能小
3. **轻量级**：Agent 运行在目标 JVM 中，不能引入大量依赖
4. **安全丢弃**：当消费速度跟不上生产速度时，应丢弃旧数据而非阻塞生产者

Disruptor 是高性能的内存队列框架，提供了多生产者多消费者模式、事件处理链等高级特性。但引入 Disruptor 会带来显著的依赖成本和复杂度。

## 方案选项

### 选项 A: 使用 Disruptor

优点：
- 业界验证的高性能框架
- 支持多消费者模式、事件处理链
- 丰富的序列化策略

缺点：
- 重量级依赖，引入大量类
- 消费者模型复杂，Luna 只需单消费者
- 满队列策略默认阻塞，需自定义
- 与目标应用的 Disruptor 版本冲突风险

### 选项 B: 自研 MPSC RingBuffer

基于 AtomicReferenceArray + CAS 实现多生产者单消费者无锁队列。

优点：
- 零外部依赖
- 满队列丢弃策略天然保护业务线程
- 代码量极小（~150 行）
- 无版本冲突风险

缺点：
- 无 Disruptor 的高级特性（多消费者、事件处理链、批量消费）
- 容量固定，不可动态调整

## 决策

选择**选项 B：自研 MPSC RingBuffer**。

Luna 的数据传输场景是典型的多生产者单消费者模式：多个业务线程写入，单个 LogDispatcher 线程消费。Disruptor 的多消费者、事件处理链等高级特性在此场景下完全不需要。

**核心设计**：
- 基于 `AtomicReferenceArray<ProbeMessage>` + CAS 实现无锁写入
- 容量固定 4096，满时丢弃旧消息（`offer()` 非阻塞）
- 单消费者 `poll()` 顺序读取
- 无 WebSocket 连接时仍消费（丢弃），防止 RingBuffer 积压 OOM

**关键不变量**：RingBuffer 满时丢弃不阻塞业务线程。

## 影响

- 注入代码路径零阻塞保证
- 高并发场景下可能丢失消息（可接受，观测数据允许丢失）
- 无外部依赖冲突风险
- 后续如需多消费者场景，可评估引入 Disruptor 或扩展 RingBuffer
