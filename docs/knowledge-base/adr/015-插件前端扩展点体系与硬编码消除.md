# ADR-015: 插件前端扩展点体系与硬编码消除

## 状态

Accepted

## 背景

当前前端存在 11 处探针类型硬编码，新增插件必须修改前端代码：

1. **后端 API 数据不完整**：`PluginUIController` 返回的 `displayName` 和 `syntax` 都是占位符（`probeType` + " probe"），前端无法从 API 获取有意义的展示信息。

2. **前端 plugin-registry.js 硬编码**：`_probeDisplayName()` 硬编码 `{ LOG, SNAPSHOT, TRACE }`，`_probeSyntax()` 硬编码 3 条语法说明，`_builtInDefaults()` 硬编码 3 个 probeHandler。

3. **快捷菜单硬编码**：`ClassDetail.vue` 中 4 个快捷选项写死，`handleTraceTiming()` 硬编码 TRACE 双注入逻辑。

4. **InjectionDialog 硬编码**：watcher 中硬编码 TRACE 的 `start/end` 代码生成，`getProbeDisplayName()` 硬编码显示名映射。

5. **InjectionDetailOverlay 硬编码**：`normalizeLocation()`、`getLabel()`、`getCodeDisplay()` 均硬编码 TRACE 逻辑。

6. **LogViewer 硬编码**：消息分发使用 `if-else` 链硬编码 `SNAPSHOT/TRACE/LOG/CALL_CHAIN` 分支。

7. **SnapshotSerializer 耦合**：`SnapshotSerializer` 位于 `snapshot` 插件包内，其他插件（如未来的 CallChainPlugin）需要跨包引用，违反插件隔离原则。

根因：后端 `ProbeHandler` 接口缺少前端展示元数据，`ui-manifest` API 数据不完整，前端被迫硬编码。

## 方案选项

### 选项 A：前端配置文件映射

在前端维护一个 `probe-config.js` 配置文件，将 `probeType` 映射到显示名、图标、行为等。

优点：
- 改动小，不需要改后端

缺点：
- 新增插件仍需修改前端配置文件
- 前后端数据分散，容易不一致
- 违反"插件自包含"原则

### 选项 B：ProbeHandler 声明式元数据 + API 暴露 + 前端数据驱动（推荐）

后端 `ProbeHandler` 新增声明式元数据方法，`ui-manifest` API 完整暴露，前端从 API 动态渲染。

优点：
- 新增插件前端零改动
- 单一数据源（后端 ProbeHandler），前后端一致
- 符合知识库 `flows.md` 中"数据驱动，框架渲染"的设计原则
- 符合 `boundaries.md` 中插件化重构的方向

缺点：
- 改动范围较大（后端接口 + API + 前端多个组件）

## 决策

选择选项 B。

理由：
1. 当前硬编码问题已真实存在（4 个内置插件就有 11 处硬编码），每新增一个插件都要改前端，维护成本持续增长。
2. 知识库 `flows.md` 已定义了 EP-1/EP-2 扩展点框架，但前端未实现，本次改造是补齐缺失。
3. 改造后新增插件（如 CallChainPlugin）无需修改任何现有前端代码。

## 影响

### 后端变更

#### 1. ProbeHandler 接口新增 7 个 default 方法

```java
public interface ProbeHandler {
    // 现有方法（不变）
    String getProbeType();
    boolean usesCode();
    Set<String> supportedInjectionLocations();
    ValidationResult validate(InjectRequest request);
    void handle(CompiledCode code, GenerateContext ctx);
    default void onDelete(PersistentInjection injection, InjectionRepository repository, InjectionRegistry registry) {}

    // 新增：前端展示元数据
    default String getDisplayName() { return getProbeType(); }
    default String getSyntax() { return ""; }
    default String getIcon() { return ""; }
    default String getCategory() { return "injection"; }
    default Map<String, String> getDefaultCode() { return Collections.emptyMap(); }
    default Map<String, String> getLocationLabels() { return Collections.emptyMap(); }

    // 新增：快捷菜单行为
    default QuickActionBehavior getQuickActionBehavior() {
        return getConfigSchema().isEmpty() ? QuickActionBehavior.DIRECT : QuickActionBehavior.FORM;
    }

    // 新增：配置表单 schema
    default List<FormFieldSchema> getConfigSchema() { return Collections.emptyList(); }
}
```

#### 2. QuickActionBehavior 枚举

```java
public enum QuickActionBehavior {
    DIRECT,  // 一键注入，不弹表单
    FORM     // 弹配置表单
}
```

#### 3. FormFieldSchema 值对象

```java
public class FormFieldSchema {
    private String key;           // "thresholdMs"
    private String label;         // "耗时阈值(ms)"
    private String type;          // text / number / select / textarea
    private Object defaultValue;  // 0
    private List<Option> options; // select 类型的选项
    private boolean required;     // true
    private String placeholder;   // "请输入阈值"

    public static class Option {
        private String value;
        private String label;
    }
}
```

#### 4. 内置插件实现

| 插件 | displayName | icon | category | quickActionBehavior | configSchema |
|------|-------------|------|----------|---------------------|-------------|
| LogProbeHandler | "日志表达式" | "fa-print" | "injection" | FORM | code(textarea,required) + condition(text) |
| SnapshotProbeHandler | "内存快照" | "fa-camera" | "injection" | DIRECT | 空 |
| TraceProbeHandler | "方法耗时" | "fa-stopwatch" | "performance" | FORM | thresholdMs(number,defaultValue=0) |
| ConditionalBreakpointPlugin | — | — | — | — | 不注册 ProbeHandler |

TraceProbeHandler 额外实现：
```java
@Override public Map<String, String> getDefaultCode() {
    return Map.of("method_enter", "start", "method_exit", "end:0");
}
@Override public Map<String, String> getLocationLabels() {
    return Map.of("method_enter", "TRACE START", "method_exit", "TRACE END");
}
```

#### 5. PluginUIController 补全 VO

```java
// 修改前
.map(h -> new UiManifestVO.ExpressionProtocolEntry(
    h.getProbeType(), h.getProbeType(), h.getProbeType() + " probe"))

// 修改后：新增 ProbeTypeEntry，包含完整元数据
.map(h -> new UiManifestVO.ProbeTypeEntry(
    h.getProbeType(),
    h.getDisplayName(),
    h.getSyntax(),
    h.getIcon(),
    h.getCategory(),
    h.usesCode(),
    h.supportedInjectionLocations(),
    h.getDefaultCode(),
    h.getLocationLabels(),
    h.getQuickActionBehavior(),
    h.getConfigSchema()))
```

#### 6. SnapshotSerializer 移至 infra 包

```text
移动：fun.efto.luna.core.plugin.builtin.snapshot.SnapshotSerializer
  → fun.efto.luna.core.infra.serialization.SnapshotSerializer

联动更新：
  - SnapshotSerializer 自身：新增 static{} 自注册到 BootstrapClassRegistry
  - SnapshotProbe.static{}：删除 SnapshotSerializer 的注册行
  - StackFrameCapture：更新 import
  - BootstrapJarBuilder.INCLUDE_EXACT：更新路径
  - SnapshotSerializerTest：更新 import
```

理由：SnapshotSerializer 已被 2 个插件使用（Snapshot + 未来 CallChain），满足三次法则。

### 前端变更

#### 1. plugin-registry.js 消除硬编码

删除 `_probeDisplayName()`、`_probeSyntax()` 硬编码映射，改为从 API 数据读取：

```javascript
_convertToExpressionProtocols(probeHandlers) {
    return probeHandlers.map(p => ({
        protocol: p.probeType.toLowerCase(),
        displayName: p.displayName || p.probeType,   // 从 API 读取
        syntax: p.syntax || '',                       // 从 API 读取
        icon: p.icon || '',                           // 从 API 读取
        category: p.category || 'injection',          // 从 API 读取
        probeType: p.probeType,
        usesCode: p.usesCode,
        supportedInjectionLocations: p.supportedInjectionLocations || [],
        quickActionBehavior: p.quickActionBehavior || 'FORM',
        configSchema: p.configSchema || [],
        defaultCode: p.defaultCode || {},
        locationLabels: p.locationLabels || {}
    }))
}
```

#### 2. ClassDetail.vue 快捷菜单改为数据驱动

```html
<!-- 修改前：硬编码 4 个选项 -->
<div class="popover-item" @click="handleQuickAction('LINE_BEFORE')">行前注入</div>
<div class="popover-item" @click="handleQuickAction('LINE_AFTER')">行后注入</div>
<div class="popover-item snapshot" @click="handleQuickAction('LINE_BEFORE', 'SNAPSHOT')">快速快照</div>
<div class="popover-item trace" @click="handleTraceTiming">方法耗时</div>

<!-- 修改后：从 plugin-registry 动态渲染 -->
<div v-for="action in quickActions" :key="action.key"
     class="popover-item" @click="action.handler">
  <i :class="['fas', action.icon]"></i> {{ action.label }}
</div>
```

快捷菜单行为由 `quickActionBehavior` 决定：
- `DIRECT`：直接调用注入 API，不弹表单
- `FORM`：弹出轻量配置表单（字段由 `configSchema` 定义）

#### 3. InjectionDialog 简化为探针配置表单

从快捷菜单打开时：
- 探针类型和注入位置**只读**（已由快捷菜单确定）
- 只展示当前探针的 `configSchema` 定义的字段
- 不再提供类型切换下拉框

从大纲 + 按钮打开时：
- 保留完整选择能力

消除硬编码：
- 删除 `getProbeDisplayName()` 硬编码映射
- 删除 TRACE 的 `start/end` 硬编码，改为从 `defaultCode` 读取
- 删除 `onProbeTypeChange()` 中的 TRACE 特殊逻辑

#### 4. InjectionDetailOverlay 消除硬编码

- `normalizeLocation()`：从 `locationLabels` 读取
- `getLabel()`：从 `locationLabels` 读取
- `getCodeDisplay()`：从 `defaultCode` 反向映射

#### 5. LogViewer 消除硬编码

消息分发改为注册式处理器：

```javascript
const messageHandlers = {
    SNAPSHOT: (parsed) => ({ type: 'SNAPSHOT', data: parsed }),
    TRACE: (parsed) => ({ type: 'TRACE', text: parsed.payload, timestamp: parsed.timestamp }),
    LOG: (parsed) => ({ type: 'LOG', text: parsed.payload, timestamp: parsed.timestamp }),
}
// 未知类型走通用 fallback
```

### 前端扩展点体系更新

知识库 `flows.md` 中的扩展点定义更新为：

| 扩展点 | 说明 | 数据源 | 改造前 | 改造后 |
|--------|------|--------|--------|--------|
| EP-1 注入类型 | 注册新的注入位置选项 | `ProbeHandler.supportedInjectionLocations()` | InjectionDialog 部分实现 | 快捷菜单 + 对话框均动态渲染 |
| EP-2 表达式协议 | 注册新的代码协议 | `CodeEngine.getName()` | InjectionDialog 部分实现 | 同上 |
| EP-5 探针行为 | 快捷菜单行为 + 配置表单 | `ProbeHandler.getQuickActionBehavior()` + `getConfigSchema()` | 不存在 | **新增** |
| EP-6 探针元数据 | 显示名、图标、分类、默认代码 | `ProbeHandler.getDisplayName()` 等 | 硬编码 | **新增**，从 API 动态读取 |
| EP-3 模板库 | 插件提供的 RuleTemplate | `PluginManager.listPlugins()` | 未实现 | 延后 |
| EP-4 插件管理 | 插件列表、启用/禁用 | `/api/plugins/*` | 未确认 | 延后 |

### 风险分析

| 风险类型 | 风险描述 | 应对措施 |
|----------|----------|----------|
| 兼容性 | ProbeHandler 新增 default 方法 | 所有新方法有默认实现，现有插件无需修改 |
| API 兼容 | ui-manifest 返回新字段 | 新字段前端用 `||` 兜底，旧版前端忽略新字段 |
| 降级路径 | API 不可用时前端降级 | `_builtInDefaults()` 同步更新新字段 |
| SnapshotSerializer 移动 | BootstrapClassRegistry 路径变更 | 更新 BootstrapJarBuilder.INCLUDE_EXACT |
| 表单 Schema 扩展性 | 只支持 4 种基础类型 | 满足当前需求，未来按需扩展 |
